# KISMATIK — память сообщества

KISMATIK превращает публичную Telegram-группу в память с ответами: бот читает переписку, отвечает на вопросы со ссылками на сообщения, собирает вики и подсказывает, кто кому может помочь.

Работает внутри процесса PiPi, но группы KISMATIK изолированы от него: их сообщения не попадают в PiPi gateway, общую вики и инструменты владельца.

## Что умеет

| Действие | Как |
|---|---|
| Вопрос | `@бот вопрос`, ответ на сообщение бота, `/km ask вопрос` |
| Что бот знает | `/km wiki` — страницы, собранные из переписки (только при `KISMATIK_WIKI=on`) |
| Забыть сообщение | `/km forget` ответом на своё сообщение (владелец может любое) |
| Совпадения | Сам: раз в 2 часа вылавливает «ищу…» и «могу…», при совпадении отвечает на «ищу» и тегает обоих |
| Выключить / включить | `/km off`, `/km on` — только владелец (`OWNER_TG_IDS`) |
| Статистика | `/km stats` — только владелец |

Ответ строится только из найденного в этой группе; без источника бот говорит «не нашёл». Лимиты: 30 вопросов на человека в день, 5 подсказок-совпадений на группу в день.

## Как устроена память

```
сообщение → messages → чанк (разговор без паузы >10 мин, ≤1500 символов)
                         ├─ FTS5 по стемам (snowball RU/EN)
                         ├─ вектор EmbeddingGemma (256d), фоном раз в минуту
                         └─ раз в 2 ч: [KISMATIK_WIKI=on] brain-ingest → вики группы (scope kismatik-<chatId>)
                                       + извлечение need/offer → матчинг → подсказка
вопрос → FTS чанков + векторы + FTS вики → RRF → LLM с цитатами [msg:id] → проверка id → ссылки
```

Данные: `DATA_DIR/kismatik.sqlite`, вики в `DATA_DIR/pipi-brain/spaces/kismatik-<chatId>/`, модель в `DATA_DIR/models/`.

## Подключение группы

1. Узнать chat id группы (например, переслать сообщение из группы боту @RawDataBot или из логов). Для супергрупп он вида `-100…`.
2. В `.env` на сервере:
   ```
   KISMATIK_CHAT_IDS=-100…,-100…
   ```
3. Добавить бота в группу **администратором** (без прав — достаточно) или отключить privacy mode в BotFather (`/setprivacy` → Disable) и переподключить бота. Иначе Telegram присылает боту только команды и ответы ему.
4. Перезапустить PiPi. В логах: `KISMATIK enabled`.
5. Написать в группе `/km help`.

## Канал с комментариями

Комментарии к постам канала живут в связанной группе обсуждения. Подключается именно она:

1. `KISMATIK_CHAT_IDS=<id группы обсуждения>`, бот — администратор группы. Посты канала приходят туда автоматической пересылкой и сохраняются как посты канала (ссылка в ответах ведёт на `t.me/<канал>/<id>`); комментарии склеиваются в один чанк с постом независимо от пауз.
2. Можно добавить и id самого канала (бот — админ канала): тогда посты сохраняются и оттуда. Канал — отдельное сообщество со своим chat id.
3. Импорт: экспорт группы — как обычно; экспорт канала — с id и username канала: `pnpm kismatik:import channel.json -100… foodconnections`. В экспорте группы у пересланных постов нет username канала, поэтому ссылки на них ведут в группу.

## Импорт истории

Бот не видит сообщения до своего появления в группе. Историю даёт админ:

1. Telegram Desktop → группа → ⋮ → Export chat history → формат **JSON**, медиа не нужны.
2. Скопировать `result.json` на сервер и выполнить:
   ```bash
   docker compose exec pipi-bot node dist/scripts/kismatik-import.js /app/data/result.json
   ```
   (локально: `pnpm kismatik:import result.json`). Повторный запуск безопасен.
3. Бот сам догонит: эмбеддинги — минуты, вики — пачками раз в 5 минут, пока есть бэклог.

Подсказки-совпадения из истории делаются только для «ищу» не старше 14 дней и не чаще лимита.

## Эмбеддинги

| `KISMATIK_EMBEDDER` | Что | Когда |
|---|---|---|
| `local` (по умолчанию) | EmbeddingGemma 2 в процессе (onnxruntime, `KISMATIK_LOCAL_DTYPE=fp32`), до ~1.1 ГБ RAM, ~0.5 с на пост | VPS от 4 ГБ RAM |
| `gemini` | Gemini API (`KISMATIK_GEMINI_EMBED_MODEL`), нужен `GEMINI_API_KEY` | слабое железо |
| `none` | только полнотекстовый поиск | отладка |

Тексты эмбеддятся по одному и обрезаются до 2000 символов. Замер на 1050 постах @foodconnections (Apple Silicon): 8.6 мин, RSS 1.1 ГБ; q8 на ARM в разы медленнее fp32, q4 — чуть быстрее, качество не проверено.

Первый запуск скачивает модель (~850 МБ: pipeline тянет и неиспользуемые аудио/видео-энкодеры) в `DATA_DIR/models`. Смена модели или размерности → векторы пересчитываются заново (старые игнорируются).

## Проверка качества поиска

```bash
KISMATIK_EMBEDDER=local pnpm kismatik:eval questions.json -100…
```

Набор `{id, type, question, gold_post_ids}`; печатает recall@8 по типам вопросов и латентность. На 40 вопросах по @foodconnections: только FTS — 73%, гибрид с EmbeddingGemma 2 — 87% (p95 63 мс).

## Качество и стоимость (e2e на @foodconnections, 2026-10-10)

1050 постов, 40 вопросов + 20 пар need/offer, `google/gemini-2.5-flash` через OpenRouter:

| | Результат |
|---|---|
| Ответ с верной ссылкой на подтверждающий пост | 27/31 (87%); ещё 2 частично, 2 честных «не нашёл» |
| «Не нашёл» на вопрос без ответа в канале | 9/9 |
| Галлюцинации | 0 |
| Матчинг: точность / полнота | 9/10 / 9/10 |
| Ответ | ≈ $0.0013, 1–2 с |
| Извлечение need/offer | 1 вызов на пачку (~16k символов) |
| Вики (`KISMATIK_WIKI=on`) | ≈ $0.02 на пост (advisor-модель), страницы на английском — поэтому выключена по умолчанию |

**Лимиты PiPi действуют и на KISMATIK:** 120 LLM-вызовов/час и `PIPI_DAILY_COST_LIMIT_USD` (по умолчанию $3/день) — при превышении kill switch останавливает весь PiPi. Догонка истории идёт пачкой раз в 5 минут (~1–6 вызовов), т.е. с запасом; при включённой вики поднимите дневной лимит.

## Хостинг

Прод — VPS в OVH на существующем `docker-compose.yml`. Нужно от 4 ГБ RAM (PiPi + EmbeddingGemma ≈ 1 ГБ с запасом), Linux x86_64 или arm64, регион EU. Входящие порты не нужны (long polling).

Бэкап: Litestream → S3-совместимое хранилище (OVH Object Storage или Cloudflare R2) для `open-pipi.db` и `kismatik.sqlite` + снапшоты VPS. Один раз проверить `litestream restore`.

## Откат

`/km off` в группе — бот перестаёт читать и отвечать. Полностью: убрать группу из `KISMATIK_CHAT_IDS` и перезапустить — группа вернётся к обычному поведению PiPi. Данные остаются в `kismatik.sqlite`.
